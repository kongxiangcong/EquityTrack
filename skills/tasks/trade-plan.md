# 交易计划任务

## 创建计划

1. 从自然语言只解析账户别名、证券代码和计划目的；不让用户提交研究运行、趋势评估、内部策略版本、数量意图或规则图。
2. 应用自动选择最新完整的已持久化研究、绑定的近期趋势、最新已确认账户快照、已确认风险政策和活动内置策略。默认保留全部已确认持仓为核心数量，任何候选变化数量保持未知并等待用户复核；应用负责完整编译、校验并保存开放草稿。
3. 用用户语言展示期限、复核日期、数量边界、触发后的人工任务、风险约束、证据新鲜度和限制。草稿不生效，也不产生订单。
4. 展示最终修订及与现行计划的差异后，只询问一次：“是否确认这份最终修订？”

## 更新计划

1. 新证据触发复核时，从冻结复核项创建影响判断，再生成有限、规范的修改提案；用户自然语言直接要求修改时，重新走同一应用拥有的草稿与修订策略，自动采用最新完整研究并保留历史版本。
2. 差异必须按“新增、修改、删除、保持不变”展示，并解释依据、风险影响和仍缺少的证据。不得用一段新文本覆盖历史版本。
3. 接受修改提案只会创建或修订开放草稿；不会跳过最终确认，也不会激活计划。
4. 任一内容变化都使旧确认失效。用户拒绝、未回答、确认过期或确认内容不精确时，保持待确认状态。
5. 只有账户事实确认、最终计划确认和实际成交声明需要用户决定。研究、估值门、草稿生成和差异计算不中途反复确认。
6. 计划检查使用“符合已确认计划 / 触发复核 / 证据不足”，不得变成买卖、持有、加减仓建议。
