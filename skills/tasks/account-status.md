# 账户与今日状态任务

## 入口判定

- “查看、现在、当前、还有多少、持仓怎样”路由到 A：只读当前账户。
- “更新、刷新、今天收盘、检查计划”路由到 B：先更新证据，再返回今日状态。
- 账户名优先按本地 alias 解析；只有确实存在重名时才向用户澄清。不要让用户提供内部账户 ID。

## A. 查看当前账户

1. 打开数据根时自动完成必要的安全生命周期：验证当前 schema；若版本落后，先创建不可覆盖的安全备份，再加锁只向前迁移并运行 doctor；失败则保持原数据根和备份，不绕过。
2. 首选命令行：`python -m trading_platform.cli account-show --data-root <root> [--account <alias>]`。`--account` 默认 `kong`，接受 alias 或内部账户 ID；该命令经正式账户状态接口读取最新已确认快照，以及快照之后用户已明确声明的执行事实，输出标准 JSON 信封。只有需要组合工作台视图（计划摘要、未决任务、复核状态）时，才经 `open_read_models` 的 `portfolio`/`holding` 读取模型补充。
3. `account-show` 已用证券主数据把内部身份投影为交易所代码（`market`/`code`）；经其他接口读取时必须先完成同样的投影再呈现。默认输出：
   - 截至日期和口径；
   - 净值、现金、持仓市值、现金比例和总仓位；
   - 每个持仓的代码、数量、市值、仓位、成本口径收益；
   - 数据质量和无法计算项。
4. 如果执行记录缺少价格或费用，现金和依赖收益保持未知。若只有已确认快照，没有更新后的行情，明确标注为快照口径。

## B. 更新今天状态

本任务自动使用最新完整 A 股交易日，更新市值、收益、仓位与集中度。没有新的券商或成交事实时，只更新证据与估算。

1. 从已确认非零持仓与默认观察池推导同步范围。对每只证券使用固定的结构化数据源策略，冻结不晚于请求时点的最新完整 A 股交易日。凭据只从批准的本地 credential seam 读取，不得出现在命令、日志或回复中。
2. 同步失败时优先使用仍满足新鲜度和完整性门的本地缓存；若没有合格缓存，继续生成“证据不足”结果并列出受影响标的，不伪造当日行情。
3. 以已确认数量乘冻结收盘价估算市值；现金只有存在新确认账户事实或价格、费用完整的已声明执行时才更新。计算净值、总仓位、现金比例、单一持仓集中度、成本口径浮动收益及持仓贡献；任一依赖未知时给出精确原因。
4. 对每个活动计划从同一冻结行情建立市场快照并运行确定性规则评估，再执行唯一的人工组合复核任务。计划不存在、评估缺失或证据不完整时保持相应的待复核或无法判断状态。
5. 返回实际使用的交易日、组合关键指标、持仓变化、计划检查结果和待处理事项。技术身份只保存在内部详情。

## 中性结果映射

- 没有规则触发且证据完整：`未触发复核条件 / 符合已确认计划`。
- 确定性规则触发并产生任务：`触发复核，需要用户判断`。
- 行情、账户、计划或规则输入不足：`证据不足，暂时无法判断`。

这些是纪律状态，不是证券行动建议。
