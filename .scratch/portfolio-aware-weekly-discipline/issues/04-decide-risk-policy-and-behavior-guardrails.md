# 决定组合风险政策与行为纪律边界

Type: `grilling`
Mode: `HITL`
Status: `resolved`
Blocked by: 02, 03

## Question

用户愿意预先冻结哪些风险与行为约束，才能把盈亏感受替换成可审计纪律？逐项决定单证券/行业/组合暴露、现金保留、计划最大损失、组合回撤、流动性、事件风险、计划外行为、规则修改冷静期和例外审批的领域语义、单位、适用范围与版本化方式。每项都给出推荐值形态和权衡，但不得由 Agent 替用户选择风险偏好，也不得把约束转换为个性化买卖指令。

## Current canonical baseline

- 当前 `PlanDraftContent` 已要求填写 CNY 计价的 `max_planned_notional` 与 `max_planned_loss`，确认后会把两者随不可变 `TradePlanVersion` 写入 `plan_risk_constraint`。
- 当前唯一确定性不变量是 `max_planned_loss <= max_planned_notional`。它尚未绑定账户净值、用户风险政策版本或失效条件计算，也不会在确认时判断是否超出用户预先冻结的风险预算。
- 当前计划指标目录只有 `position.quantity` 与 `portfolio.net_asset_value` 两个账户指标；没有仓位权重、现金比例、行业/组合暴露、组合回撤、个股流动性、事件窗口、冷静期或例外审批指标。
- 当前规则效果只支持提示复核、标记失效候选、标记风险限制违反、阻断用户候选意图与观察；规则评估不会产生订单或自动执行副作用。
- 因此本票必须决定一个新的、版本化且由用户确认的组合风险政策，而不能把现有计划字段误称为已经存在的组合级风险纪律。未知账户字段必须继续导致依赖约束 `unable`/`blocked`，不能按零值通过。

## Answer

### 用户选择与总原则

用户明确授权本票后续问题直接采用推荐答案。第一版采用一套由用户确认、不可变且按账户生效的 `PortfolioRiskPolicy`（组合风险政策），用预先冻结的约束替代临场盈亏感受。它只约束计划版本确认、日终评估和用户候选意图，不生成订单、不替用户决定交易，也不改变金融输出边界。

政策采用以下共同语义：

- 基础币种为 CNY；百分比统一以计划所引用的同一 `AccountSnapshot` 的冻结组合净资产为分母。
- 敞口按冻结市场价格计算。拟议风险增加只能使用计划声明的最大名义金额形成压力上界，不能假设成交；实际指标和规则效果由“决定计划编制、指标目录与确定性评估合同”锁定。
- 所有依赖字段必须 `ready`。净资产、完整持仓全集、价格、行业分类、历史净值、成交额或事件时间未知时，对应约束为 `unable`/`blocked`，不得按零值或“不适用”放行。
- 约束分为硬门禁和提示复核。硬门禁在确认新的 `TradePlanVersion` 前执行；已有不可变版本及其历史评估不会被后来政策改写。

### 第一版冻结阈值

| 约束 | 冻结值与单位 | 适用语义 | 失败语义 |
|---|---|---|---|
| 单证券敞口 | 组合净资产的 `15%` | 同一账户、同一证券的冻结当前敞口加拟议风险增加压力上界 | 超限或无法计算时，硬阻断风险增加型版本确认 |
| 单行业敞口 | 组合净资产的 `30%` | 按合格、版本化、PIT 行业分类汇总；不得用名称猜测行业 | 超限或分类能力不 ready 时，硬阻断依赖该判断的风险增加型版本确认 |
| 组合总敞口 | 组合净资产的 `90%` | 所有 A 股证券冻结市值加拟议风险增加压力上界；不做净额抵销 | 超限或持仓全集/估值不完整时硬阻断 |
| 最低现金保留 | 组合净资产的 `10%` | 使用同一 cutoff 的可用现金；冻结现金不能计入可用现金 | 低于阈值或现金能力不 ready 时硬阻断风险增加型版本确认 |
| 单计划最大损失 | 组合净资产的 `0.5%` | `max_planned_loss` 必须同时不超过该预算和 `max_planned_notional` | 超限硬阻断任何新版本确认；仅提示复核被拒绝 |
| 活跃计划合计最大损失 | 组合净资产的 `2%` | 对同一账户所有仍有效计划的冻结最大损失求和，不按相关性抵销 | 超限或活跃计划集合不完整时硬阻断 |

这些数值是用户本次确认的纪律政策，不是平台默认投资建议。未来不得把它们硬编码为所有用户或账户的系统常量。

### 组合回撤纪律

组合回撤只能由完整、连续、同口径且通过校验的历史账户净值序列计算；用户声明快照、券商截图或相邻快照差额不能开启该能力。

- 从已验证高水位回撤达到 `8%`：进入 `review_required`，日终与周末工作区显著提示复核，但不改写既有计划。
- 回撤达到 `12%`：进入 `risk_increase_frozen`，硬阻断新的风险增加型版本确认；仅允许不会增加上述冻结风险上界的草稿继续进入用户确认。
- 历史净值能力不可用：回撤状态为 `unable`，不得伪造为零回撤；其他不依赖回撤的约束仍可独立评估。
- 高水位、净值口径、起始日期和每次状态变化都随政策与评估证据冻结，不能事后重选区间。

### 流动性纪律

流动性采用证券最近 `20` 个完整交易日的 PIT 日成交额中位数，币种为 CNY，并使用计划 cutoff 前已完整可用的数据：

- 单个计划的最大名义金额不得超过该中位日成交额的 `5%`。
- 该证券的冻结当前敞口加拟议风险增加压力上界，不得超过中位日成交额的 `50%`；这等价于在每天不超过 `10%` 中位成交额的压力假设下至少需要五个交易日。
- 上市不足 20 个完整交易日、停牌、成交额缺失、价格/复权/公司行动冲突或流动性输入 stale 时，约束为 `blocked`；不得缩短窗口后静默放行。
- 该压力口径只描述可审计的容量边界，不预测真实成交、冲击成本或可执行性。

### 事件风险纪律

事件风险只引用带来源、证券身份、`announced_at`、预定发生时点和 PIT 可得性的结构化事件。传闻、无来源文本和仅由模型生成的事件不能解除或触发硬门禁。

- 对定期报告、股东大会审议的重大事项、已公告的停复牌/重大资产重组、控制权变化以及其他会改变计划失效条件的已知重大事件，事件窗口从预定发生日前一个交易日开始，直到事件发生后第一个完整交易日的数据与官方披露均已冻结。
- 窗口内的新风险增加型版本必须 `event_review_confirmed`，记录用户已查看的官方证据、仍存不确定性和计划失效条件；缺少官方证据或事件时间冲突时硬阻断。
- 事件复核不会把不确定事件转换成方向判断，也不会产生个性化行动语言。

### 计划外行为与行动记录

计划外行为只能来自用户显式记录的 `ActionLogEntry`，不能从账户快照差额推断成交或行为：

- 每条记录必须引用账户、证券、发生时间、当时有效计划版本（若有）、用户声明的行为类别、原因和是否计划外。
- 计划外候选意图进入 `cooling_off`，至少等待下一个完整交易日，并重新通过届时有效的账户、市场、研究和风险政策门禁；它不能直接成为已确认计划版本。
- 日终与周末复盘展示次数、原因和相对既有计划的偏差，但不输出惩罚性评分、收益归因或自动限制。
- 未记录不等于没有计划外行为；历史流水 capability 不完整时只报告“无法核验”。

### 规则修改冷静期

- 收紧风险政策可以在用户确认后立即生效，但只约束之后确认的计划版本和评估，不追溯改写历史。
- 放宽任何阈值、关闭硬门禁或扩大例外范围，必须新建政策草稿，记录旧值、新值和理由，并等待一个完整交易日后再次确认；期间旧政策继续有效。
- 同一政策草稿在冷静期内再次放宽会重新开始冷静期。取消草稿或恢复更严格值不需要等待。
- 普通计划内容修改仍形成新的 `TradePlanVersion`；是否还需要计划级冷静期由计划编制票决定，不与政策版本混用。

### 例外审批

`RiskPolicyException`（风险政策例外）是用户对一个明确软约束、账户、证券/计划和有限时间窗口的不可变自我审批记录，不是永久白名单：

- 必填约束 id、适用身份、理由、支持证据、创建时间、生效/失效时间、用户再次确认和当时政策版本。
- 第一版最长只到下一个完整交易日收盘；不得自动续期、批量覆盖证券或复用于另一计划。
- 例外只能跳过明确标为可例外的提示复核。它不能绕过单计划/组合最大损失、敞口、现金、流动性、回撤冻结、事件证据缺失、账户/数据 capability 缺失、A 股-only 范围、用户确认或禁止自动执行等硬边界。
- 需要放宽硬边界时只能创建新的风险政策版本并完成冷静期，不能把例外伪装成第二条运行路径。

### 版本、引用与失效

每个政策版本至少冻结：

- `risk_policy_id`、版本号、账户 id、基础币种、状态与内容哈希；
- 全部阈值、单位、分母语义、适用范围、舍入规则和各约束的硬/软门禁类别；
- 创建、首次确认、冷静期结束、生效、替代与失效时间；
- 前一政策版本、变更差异、变更理由和用户确认记录。

每个 `TradePlanVersion` 必须精确引用确认时有效的风险政策版本、账户快照和所需数据/市场身份。政策被替代后，旧计划和旧评估继续引用原版本；新的计划版本使用新政策。政策、账户或输入身份不一致时必须失败关闭，Web/CLI 不得自行选择“最新”对象拼装。

### 对后续地图的影响

- “决定计划编制、指标目录与确定性评估合同”必须把上述语义落实为一个 canonical 指标与效果目录，并区分风险增加型候选意图、纯观察和不会增加冻结风险上界的修订。
- “决定每日评估、行动日志与周末复盘工作流”必须定义 `ActionLogEntry` 的确认、幂等与复盘投影，不得从快照差额推断行为。
- 隐私运维票必须将政策、例外与行动记录纳入 local-only、备份、恢复、删除/失效和日志脱敏边界。
- 本票没有资格宣称当前代码已实现这些政策；它只关闭风险与行为纪律的产品决策。
