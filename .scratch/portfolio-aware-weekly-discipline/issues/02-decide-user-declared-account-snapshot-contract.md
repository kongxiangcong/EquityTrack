# 决定用户声明账户快照的信任与降级合同

Type: `grilling`
Mode: `HITL`
Status: `resolved`
Blocked by: 01

## Question

在用户已确认“账户快照可以手工填写、不强制完整 XLS”的前提下，`UserDeclaredAccountSnapshot` 最少必须填写哪些身份、截至时点、现金、持仓数量、可用/冻结数量、成本基础、币种和用户声明字段；哪些字段可以未知；如何区分新增、修订和纠错；哪些组合风险与计划规则可被确定性评估；哪些历史收益、费用、税费、成交批次和对账能力必须保持 limited/unavailable？同时决定手工快照、券商导入快照和后续增量快照的不可变引用与 capability 差异。

## Answer

### 结论

采用“**来源信任等级与字段能力分离、未知不等于零、所有确认快照不可变**”的合同。用户不需要按 schema 手工格式化输入：可以直接提供截图、自然语言数值或券商文件，由 Codex 控制面提取为结构化 `AccountSnapshotDraft`，普通业务代码只负责确定性校验、持久化和 capability 计算，不引入业务运行时 LLM。

截图或自然语言中的一次明确“填写/更新”请求可以作为提交意图；只作为例子提供的材料不能自动入账。提取结果若存在账户身份、日期/时区、证券身份、数量或算术冲突，Codex 只要求用户用自然语言确认歧义，草稿在此之前不得被计划或评估引用。用户无需编辑 JSON、表格或固定格式表单。

用户在本票中用一张券商 App 持仓截图验证了该入口。该图仅用于合同推演，不作为一次真实账户更新；其中的真实金额、持仓和遮蔽账户标识不进入本票、地图、Git、通用日志或验收 artifact。

### 最小快照合同

快照级必填：

- 稳定的本地 `account_id` 与用户可识别的账户别名；遮蔽后的券商尾号不能单独充当身份。
- `as_of` 的日期、时间、时区和交易时段语义，以及独立的 `declared_at` / `retrieved_at`。截图只显示手机时间但没有日期时只能形成草稿；文件时间不能静默冒充账户截至时点。
- `source_kind`、原始来源引用、用户提交意图、schema/policy 版本和内容哈希。
- 账户基础币种。每个货币字段还必须带明确币种；允许从截图清楚显示的账户币种继承，但必须保留字段 lineage。
- 零持仓账户可以成立；若存在持仓，每条必须解析到稳定 `security_id` 并具有有限、非负的总数量。A 股数量必须满足适用的整股语义。

允许显式 `unknown`：现金、可用数量、冻结数量、成本基础、当前价格、市场价值、当日盈亏、来源权重和券商汇总值。任何未知均不得写成零、空字符串或由 UI 文案解释为零。

字段关系：

- 总数量必填。可用与冻结若都已知，必须非负且相加等于总数量；若只知道其中一个，可以由总数量确定性推导另一个并标记 `derived`；若两者都未知，依赖可用性的能力保持 unavailable。
- 成本若提供，必须注明是单位平均成本还是总成本并带币种。它只表达用户声明的当前成本基础，不创建或重建成交批次。
- 当前价、市场价值、券商盈亏与权重是同一截至时点的观察字段，不是交易流水。可以留存并参与内部一致性校验，但不能单独证明历史收益。
- 多币种字段不得静默按 1:1 合并。组合净值、权重与集中度只有在存在同一 cutoff 的冻结 FX 输入时才能换算到基础币种，否则保持 unavailable。

### 截图与自然语言输入语义

券商 App 截图归类为 `user_declared_from_broker_screenshot`，不会因为带券商品牌就升级为 `broker_imported` 或 `reconciled`。实际使用时原图只进入 local-only 私有对象存储，以内容哈希、MIME、获取时间和字段级来源指针引用；不得复制进 Git、普通研究 artifact、遥测或 Provider 请求。

本次示例证明截图可以同时声明账户币种、现金、组合汇总、持仓总量/可用量、单位平均成本、当前价和市场价值；其可见合计可做确定性算术校验。总量等于可用量时可以推导冻结量为零；平均成本仍不能重建 lot。截图中缺少完整日期，因此即使算术自洽，也不能直接成为可用于日终评估的确认快照。

截图解析后的状态只可称为：

- `draft`：仍缺身份、截至时点或有歧义；不可被下游引用。
- `confirmed_user_declared`：用户提交意图成立且最小字段通过；可以按字段能力使用。
- `internally_consistent` / `inconsistent`：独立的算术校验结果；`internally_consistent` 不是“已对账”。

### 新增、修订与纠错

三者均创建新的不可变快照：

- **新增**：第一次声明或新的 `as_of` 状态观察；用 `previous_snapshot_id` 形成账户时间序列。
- **修订**：`as_of` 不变，补充原先的 unknown 或提高字段精度；用 `revises_snapshot_id` 和字段差异记录来源。
- **纠错**：用户明确声明旧快照在原截至时点就是错误的；用 `corrects_snapshot_id`、必填原因和字段差异记录。

旧快照可以被标为 superseded/corrected，但不得删除或覆盖。任何已确认计划、评估、工作流和复盘继续引用原 `snapshot_id` 与当时冻结的 capability；当前视图可默认选择关系链上的最新有效快照，但不得让历史引用自动漂移。

### 来源信任与 capability 双轴

来源信任与字段完整度分别记录：

- `user_declared`：手工数值、自然语言或截图。字段再完整也不升级为已对账。
- `broker_imported`：必须来自可解析的券商导出对象；只有文件内现金、持仓和汇总关系通过校验时，当前状态才可标为 `snapshot_reconciled`。这仍不代表历史完整。
- 后续增量快照：只是新的状态观察。可以确定性计算两个快照间的现金、数量与敞口变化，但不得从差额反推出成交、费用、税费、分红或转账。
- 历史能力只能由独立、完整且通过校验的成交与现金流水证据开启；连续快照碰巧能对上不能自动升级。

所有 capability 必须带 `ready` / `limited` / `unavailable`、原因、依赖字段和 snapshot id，不使用一个全局“数据完整”开关。

### 可确定性评估的能力

| 能力 | 最小条件 | 缺失时语义 |
|---|---|---|
| 当前持仓总量、持仓数量变化 | 证券身份与总数量 | 对应持仓草稿不能确认 |
| 当前可用/冻结量 | 两者已知，或总量加其中一项可推导 | unavailable；不能解释为全部可用 |
| 当前现金 | 现金金额与币种 | unavailable |
| 组合净资产 | 现金、全部持仓估值和必要 FX 均在同一 cutoff 完整，且汇总校验通过 | unavailable；券商总资产单字段不能替代缺失明细 |
| 持仓权重、现金比例、单证券/行业集中度、总敞口 | 完整持仓全集、可用估值、币种/FX；行业能力还需独立合格分类来源 | limited/unavailable，并指出具体缺口 |
| 快照时点未实现盈亏 | 明确成本语义、数量、同币种价格及同一 cutoff | 可作为当前声明/计算观察；不能升级为历史收益 |
| 现有 `position.quantity` 计划规则 | 对应证券数量可用且计划冻结该快照 | 可评估 |
| 现有 `portfolio.net_asset_value` 计划规则 | 组合净资产 capability ready 且计划冻结该快照 | 缺失时结果必须 `unknown`/`blocked` |

本票只锁定数据能力，不替用户选择任何风险阈值，也不决定未来新增指标的计划效果；`position.weight`、`portfolio.cash_ratio`、集中度等指标目录由“决定计划编制、指标目录与确定性评估合同”继续决定。盘中截图可以表达当前敞口，但是否有资格进入“收盘后 -> 下一交易日”冻结评估由“决定收盘后评估与下一交易日窗口语义”决定。

### 必须保持 limited / unavailable 的能力

仅凭用户声明、截图或相邻快照，不得声称具备：

- 完整交易历史、成交方向/价格/时间、撤单或订单状态；
- acquisition lots、lot age、历史 T+1 资格或具体批次来源；
- 已实现盈亏、时间加权/资金加权收益、日收益序列、基准归因或最大回撤；
- 费用、佣金、印花税、其他税费、分红、利息、入金、出金或转账拆分；
- 券商账实对账、现金流水对账、历史成本重建或完整性证明；
- 从快照差额推断的用户行为、计划内/计划外交易或行为偏差。

截图中显示的券商盈亏可以作为带原始标签的用户声明观察保存，但在没有计算口径、现金流和历史证据时不能驱动历史收益、绩效或行为规则。第一版行为纪律只能引用后续显式的用户行动日志；若未来存在合格完整历史，再以独立 capability 启用交叉核验。

### 失败关闭与验收反例

- 只有截图时间、没有日期：保留 draft，不创建可评估快照。
- 证券名称无法唯一解析：该持仓不能确认；不得猜代码。
- 现金未知：数量规则仍可用，净资产、现金比例和依赖它们的组合规则 unavailable。
- 成本未知：当前数量与合格估值能力不受影响，成本盈亏与收益能力 unavailable。
- 可用/冻结未知：总持仓规则可用，可用数量与历史 T+1 能力 unavailable。
- 汇总值和明细超出币种最小单位/显示精度容差：标记 inconsistent，展示差额，不静默改数；影响净资产的冲突阻断对应 capability。
- 新截图与前一快照不同：创建新状态观察，不合成交易。
- 用户纠错旧值：新建 correction；既有计划与评估仍指向旧快照。
- 券商截图算术完全自洽：仍是 user-declared；只有实际券商导出通过导入合同才可获得当前状态 `snapshot_reconciled`。

### 对地图的影响

本决定没有新增票。它解除“手工快照是否能提供交易历史”的 fog：答案是否定的；第一版行为偏差不得由快照差额推断，只能基于“决定每日评估、行动日志与周末复盘工作流”将要定义的显式用户行动日志。账户截图与自然语言入口的 local-only 保存、日志脱敏、备份和删除边界仍由“决定手工账户数据的隐私、安全与运维边界”处理。
